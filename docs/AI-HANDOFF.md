fake; milestone 6 emails built but console-only. **Nothing can be bought on the live site yet**:

## 3. Rules you must not break

- **Money is integer cents** (`src/lib/money.ts`). No floats anywhere in prices, tax or deposits.
- **Migrations only (D23).** `push: false`. After a schema change run
  `npx payload migrate:create <name> < /dev/null`, check the `.ts`, `.json` and `index.ts` entry,
  then `npx payload generate:types < /dev/null`. Always use `npm run migrate`, never bare
  `payload migrate`. CI fails on schema drift.
- **Never enable Payload `transactionOptions` for SQLite.** Inventory relies on single
  `payload.db.client.batch([...], "write")` calls with SQL-level guards (D40). Stock is **never**
  written with `payload.update`; go through `src/lib/inventory/ledger.ts` (`applyMovements`).
- **Unapproved means invisible to customers.** Unapproved prices show "Price to be confirmed".
  Unknown or stale stock blocks purchase. Inquiry-only products can't be bought. Unapproved photos
  and policies are hidden live.
- **Never invent business facts.** That covers prices, policy terms, deadlines, allergen claims,
  photos and delivery promises. Use only `data/source/`, Store settings and the decisions; otherwise
  keep it configurable and unapproved.
- **The seed is create-only (D24)** and refuses a live database that already has products unless
  `SEED_FORCE=1`.
- **`APP_ENV` allowlist (D41).** Only `local`, `staging` and `test` enable the test payment provider,
  unapproved photos, draft policies, the staging banner and `PREVIEW_ASSUME_STOCK`. Unset means live.
- **Product reads:** Products and Categories are staff-only over REST (D42). Storefront code must
  use an explicit `where` (`_status: published`, `channel != hidden`) with `overrideAccess: true`.
- **No secrets in the repo.** Only `.env.example` is tracked; real values live in the cPanel Node
  app's environment. The only browser-exposed variable is `NEXT_PUBLIC_SITE_URL`.
- **Nothing activates live payments, live Clover sync, real email, DNS changes or purchases**
  without Lody's approval. The Clover HTTP adapter and the SMTP adapter deliberately refuse to start.
- **Shared customer-facing copy:** plain, warm and honest. Accessibility target is WCAG 2.2 AA: labelled
  inputs, `role="alert"` errors, 44 px targets, no horizontal scroll at 390 px or with 200% text. D31
  documents an accepted gold-text contrast deviation.

## 4. Gotchas (learned the hard way)

- **Next.js 16 differs from your training data.** Check `node_modules/next/dist/docs/` before using
  a Next API. `AGENTS.md` and `CLAUDE.md` are regenerated by `next dev`; they're untracked locally.
- **Payload CLI commands can hang on prompts.** Always close stdin: `… < /dev/null`.
  `migrate:create` with no changes prints "No schema changes detected"; make sure no file was left.
- **Parallel schema work conflicts.** Migration `.json` snapshots chain, so two branches that each
  run `migrate:create` produce snapshots that miss each other's changes. Merge one branch, then delete
  the other's migration and regenerate it on top.
- **Drafts and versions vs stock.** Payload builds updates from the latest version, which can
  restore old stock. `src/hooks/product-stock.ts` pins live stock; don't remove it.
- **`NEXT_PUBLIC_SITE_URL` enables the CSRF allowlist.** With it set locally, the admin logs in only
  at exactly that origin. Leave it unset for tunnels.
- **Memory.** Every integration test file boots Payload and applies all migrations. On a small
  machine, run with `--maxWorkers=1` or `2`, and don't run the build alongside tests.
- **`payload run` passes only positional args;** scripts take options via env vars
  (`SEED_FORCE=1`, `CLOVER_DRY_RUN=1`).
- **Windows line endings:** git warns LF→CRLF on commit. Harmless.
- **Order and reservation private links** are HMACs of `PAYLOAD_SECRET`, so rotating it breaks
  every emailed link.

## 5. Run, test, deploy

```bash
npm ci
cp .env.example .env        # set PAYLOAD_SECRET (node -e "console.log(require('crypto').randomBytes(32).toString('hex'))")
npm run seed:catalog        # migrate + source records + 80 products (create-only)
npm run dev                 # http://localhost:3000, admin at /admin
```

**Checks**, the same as CI: `npm run generate:types`, `npm run typecheck`, `npm run lint`,
`npm test`, then migrate an empty database with `NODE_ENV=production`, check there's no schema drift,
and run `npm run build`.

**Cron jobs** (cPanel), each as `npx payload run scripts/<name>.ts`:

| Script | Schedule |
| --- | --- |
| `release-expired-holds` | Every 5 minutes |
| `send-pending-emails` | Every 10 minutes |
| `purge-carts` | Daily |
| `clover-push` | Every 1–2 minutes, after the sync is verified |
| `clover-pull` | Every 5–15 minutes, after the sync is verified |

**Deploy checklist:** `STATUS.md` → "Deploying". The essentials:
- `APP_ENV=production`, also at build time.
- `NEXT_PUBLIC_SITE_URL` set.
- `FIRST_OWNER_EMAIL` set, or run `create-owner`.
- `npm run migrate`, then check `/ops/system-check`.

## 6. How work has been done here

- Branch, PR to `main`, CI must be green, and the owner of the repo approves merges. Commit messages
  end with the `Co-Authored-By` trailer for the model that wrote them.
- Larger pushes ran as **waves of parallel agents**, each in its own git worktree outside the repo
  (`projects/lodelicious-wt/<name>`), with `node_modules` junctioned to the main checkout. Each
  agent read a shared brief: rules, memory limits, and files it must not touch. One agent per wave owned
  the schema and `service.ts`. The integrator merged branches one at a time into an integration
  branch, ran the full CI chain, edited the shared files (`SiteHeader`, `SiteFooter`, `STATUS.md`,
  `README.md`), and opened the PR.
- Each change gets a decision entry in `docs/decisions.md` (next free number: **D45**), placed
  before `## Superseded`.
- `docs/audit-2026-10-06.md` holds the security and accessibility audit. All 23 findings are fixed
  or partly fixed; the partial ones are listed there (no CSP yet, no 2FA, the decorative
  Store-settings timezone and closed-day fields, Next's default 404 for unmatched URLs).
